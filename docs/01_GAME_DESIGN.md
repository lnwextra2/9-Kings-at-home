# Kingdom Battle — Game Design Document (Godot 2D)

> Source of truth ของ **"เกมเล่นยังไง"**
> ตัวเลขทุกตัวเป็น starter value ที่จูนได้ → เก็บใน `.tres` ไม่ hardcode
> เอกสารนี้ถอดมาจากเกมเวอร์ชัน HTML/JS ที่เล่นได้จริงแล้ว (prototype ผ่านการเทสต์มาหลายสิบเวอร์ชัน)

---

## 1. Concept
- แนว: **roguelite deckbuilder + auto-battler**
- แรงบันดาลใจ: เกม 9 Kings (ทำเพื่อฝึกทำเกม 2D)
- 1 Run = ไต่ floor ไปเรื่อยๆ: วางการ์ดบนกระดาน → จบเทิร์น → ดูกองทัพตัวเองสู้อัตโนมัติ → ชนะได้รางวัล → floor ถัดไป
- แพ้เมื่อกองทัพตายหมด หรือศัตรูทะลุถึงฐาน

## 2. โครงสร้างสำคัญที่สุด — กระดาน ≠ สนามรบ
**นี่คือจุดที่ต่างจากเกม tower-defense ทั่วไป และต้องเข้าใจให้ถูกก่อนเขียนโค้ด**

```
   PLANNING BOARD (5×5)              BATTLEFIELD (2D top-down)
   ┌───┬───┬───┬───┬───┐            ┌──────────────────────────┐
   │⚔️ │🏹 │   │🔒 │🔒 │            │ 🏰   ⚔️⚔️⚔️      👹👹👹 │
   ├───┼───┼───┼───┼───┤            │      🏹🏹        👹👹    │
   │🏹 │🗼 │🌾 │🔒 │🔒 │   ──────►  │ ฐาน  🗼          👹👹👹 │
   ├───┼───┼───┼───┼───┤   spawn    │                          │
   │   │   │   │🔒 │🔒 │            │ ซ้าย=เรา      ขวา=ศัตรู  │
   └───┴───┴───┴───┴───┘            └──────────────────────────┘
   การ์ด 1 ใบ = 1 ช่อง               การ์ด 1 ใบ = N ยูนิตในสนาม
```

- **กระดาน 5×5 (25 ช่อง)** = ที่วางการ์ด เป็น puzzle เชิงพื้นที่ (การ์ดหลายใบมีผลกับ "ช่องรอบๆ")
- บางช่อง **ล็อกอยู่ตอนเริ่ม** ปลดล็อกได้ด้วยการ์ด/ความคืบหน้า
- **สนามรบเป็นคนละหน้าจอ** — ตอนจบเทิร์น การ์ดบนกระดานจะถูก "แปล" เป็นยูนิตในสนามรบ
- การ์ดทหาร 1 ใบ Lv1 = 1 ตัว, Lv2 = 3 ตัว, Lv3 = 9 ตัว (การ์ดใบเดียวออกได้ทั้งฝูง)
- **การ์ดไม่ตายตอนสู้** — ยูนิตตายในสนามรบ แต่การ์ดยังอยู่บนกระดาน เทิร์นหน้าสปอว์นใหม่เต็มจำนวน

## 3. Core Loop (ต่อ 1 เทิร์น / 1 floor)
```
PLANNING ──► COMBAT ──► REWARD ──► (floor+1) ──► PLANNING
```
1. **Planning** (turn-based, ไม่มีเวลาจำกัด)
   - วางการ์ดจากมือลงช่องว่าง
   - วางการ์ดชนิดเดียวกันทับกัน = **merge อัปเลเวล** (สูงสุด Lv3)
   - ใช้ tome/buff กับการ์ดที่วางแล้ว
   - ซื้อการ์ดจากร้าน / reroll ร้าน
   - กด "เริ่มการต่อสู้"
2. **End of Turn resolve** — trigger effect ของสิ่งก่อสร้างทุกใบบนกระดาน (ฟาร์มให้ทอง, ศาลเจ้าอัปเลเวล, ป้อมเลือดสังเวย ฯลฯ)
3. **Combat** (realtime, auto-battle, ผู้เล่นดูอย่างเดียว)
   - สปอว์นยูนิตฝ่ายเราจากกระดาน + สปอว์นเวฟศัตรู
   - ทุกคนหาเป้าเอง เดินเอง ยิงเอง
4. **Reward** — ชนะ: เลือกการ์ด 1 จาก 3 (reroll ได้), ได้ทอง / แพ้: จบ Run
5. floor + 1

## 4. Card System

### 4.1 หมวดการ์ด (kind)
| kind | ความหมาย | ในสนามรบ |
|---|---|---|
| `soldier` | ทหาร | สปอว์น N ตัวตาม level เดินไปสู้ |
| `base` | ฐานหลัก (บ้าน) | โครงสร้างมี HP ศัตรูมาตีได้ ตี = แพ้ |
| `building` | สิ่งก่อสร้างสนับสนุน | ส่วนใหญ่ไม่ลงสนาม ทำงานตอนจบเทิร์น |
| `turret` | ป้อมโจมตี | โครงสร้างอยู่กับที่ ยิงศัตรู |
| `buff` | บัฟถาวร | ไม่ลงสนาม — ใช้กับการ์ดบนกระดาน แล้วหายไป |
| `tome` | คัมภีร์ใช้ครั้งเดียว | ไม่ลงสนาม — ใช้แล้วหายไป |

> `base` / `building` / `turret` = **"สิ่งก่อสร้าง" เหมือนกัน แค่คนละหมวด**
> โค้ดต้องมี `is_structure()` helper ไม่ใช่ไล่เช็คทีละ kind

### 4.2 สี (color) — สำคัญต่อระบบ reward
`mint` `green` `gold` `gray` `red` `blue` `purple` `orange` `indigo` `rainbow`

- แต่ละสีมีธีมของตัวเอง (blue = ยุทธวิธี/น้ำแข็ง, red = เลือด/ปีศาจ, gold = เศรษฐกิจ, gray = เครื่องจักร ฯลฯ)
- `rainbow` = การ์ดหายาก ได้จาก reward พิเศษเท่านั้น ไม่โผล่ในร้านปกติ
- **สีจะกลายเป็นแกนหลักของระบบเวฟ** (ดูข้อ 8)

### 4.3 Level & Merge
- Lv 1 → 2 → 3 (cap ที่ 3)
- วิธีขึ้นเลเวล: merge การ์ดชนิดเดียวกัน, ใช้ tome "อัปเกรด", effect จากสิ่งก่อสร้าง
- **stat โตแบบ compound:** `stat × (1 + growth)^(level-1)`
- **จำนวนทหารโตแบบ ×3:** `count = [1, 3, 9]`

### 4.4 Card Data Schema
```
id, display_name, icon, color, kind
hp, attack, attack_cd, move_speed, attack_range, splash
count_per_level: [1, 3, 9]
growth: { hp, attack, attack_speed }
hooks: on_end_turn, on_death, on_spawn, on_upgrade
```

## 5. Combat Model
- **Realtime, fixed logical tick** (แนะนำ 30 ticks/วินาที) แยกจาก render framerate
- ต่อ 1 tick แต่ละยูนิต:
  1. หาเป้าที่ใกล้ที่สุดในฝ่ายตรงข้าม
  2. ถ้าอยู่ใน range → โจมตี (cooldown ตาม attack_speed)
  3. ถ้าไม่อยู่ → เดินเข้าหา
  4. ถ้าไม่มีเป้าเลย → ศัตรูเดินหน้าเข้าหาฐานเรา
- **Melee** = ตีโดนทันที / **Ranged** = ยิง projectile ที่วิ่งไปหาเป้า (มี travel time)
- **Splash** = ระเบิดโดนทุกตัวในรัศมี
- โครงสร้าง (`turret`) `immobile = true` และบางตัว `untargetable = true` (ศัตรูตีไม่ได้)
- **แพ้เมื่อ:** ศัตรูตัวใดตัวหนึ่งไปถึงเส้นฐาน **หรือ** ยูนิตที่ตีได้ของเราตายหมด
- **ชนะเมื่อ:** ศัตรูตายหมด

## 6. Hook System (หัวใจของการขยายเกม)
แทนที่จะเขียน `if card.id == "farm"` กระจายทั่ว engine → การ์ดแต่ละใบ **ประกาศพฤติกรรมตัวเอง**

| Hook | ยิงเมื่อ | ตัวอย่างการ์ด |
|---|---|---|
| `on_end_turn(state, card, idx)` | จบเทิร์น ก่อนเข้าสนามรบ | ฟาร์ม (+ทอง), ศาลเจ้า (สุ่มอัปเลเวล), ป้อมเลือด (สังเวยทหารรอบข้าง) |
| `on_death(state, unit)` | ยูนิตตายในสนามรบ | แพะ (ให้ทอง), ระเบิด (ระเบิดใส่รอบตัว) |
| `on_spawn(state, unit)` | ตอนสปอว์นเข้าสนามรบ | ทหารที่มีบัฟตอนเกิด |
| `on_upgrade(state, card, idx)` | การ์ดขึ้นเลเวล | ไข่สายรุ้ง (Lv3 = ฟักเป็นรางวัล), เครื่องย้อนเวลา (Lv3 = ย้อน floor) |

**กติกา:** engine รู้จักแค่ hook — ไม่รู้จักชื่อการ์ดใดๆ ทั้งสิ้น

## 7. Economy
| แหล่งทอง | หมายเหตุ |
|---|---|
| ฟาร์ม / ตลาด | ได้ทุกจบเทิร์น ตาม level |
| ฆ่าศัตรู | การ์ดบางใบเท่านั้น |
| ชนะเวฟ | โบนัสคงที่ |
| การ์ดตายที่มี `on_death` ให้ทอง | เช่นแพะ |

ใช้ทอง: ซื้อการ์ดในร้าน, reroll ร้าน, reroll reward, reroll สีศัตรู

## 8. Waves & Difficulty
### 8.1 การสเกล (ค่าที่จูนมาแล้วจาก prototype)
```
scale  = (1 + (floor-1) × 0.13) × 1.062^(floor-1)     # คูณ HP และ ATK ศัตรู
count  = 3 + ceil(floor² × 0.24)                       # จำนวนศัตรู
```
ผลลัพธ์เป้าหมาย (ทดสอบแล้ว):

| Floor | scale | HP ตัวแท็ง | จำนวนศัตรู |
|---|---|---|---|
| 5 | 1.93 | 72 | 9 |
| 10 | 3.73 | 138 | 27 |
| 20 | 10.88 | 403 | 99 |
| 30 | 27.30 | **1010** | **219** |

> ปรัชญา: **ศัตรูเน้นจำนวนเป็นหลัก** ท้ายเกมต้องเจอฝูง 200+ ตัว
> ⚠️ Godot ต้องรองรับ 200+ ยูนิตพร้อมกัน → ดู performance note ใน architecture doc

### 8.2 เวฟพิเศษ
- **Boss wave** (เช่นทุก 15 floor): บอส HP × 30, เดินช้า, ตีช้า + บริวาร
- **Rainbow wave**: ศัตรูแข็งกว่าปกติ ชนะแล้วได้การ์ดสายรุ้ง

### 8.3 ระบบสีเวฟ (ฟีเจอร์ที่วางแผนไว้ — ทำใน M4)
- ก่อนเข้าสู้ เกมสุ่ม **"สีศัตรู"** 1 สี → ศัตรูทั้งเวฟเป็นการ์ดสีนั้นล้วน
- ศัตรูใช้ **การ์ดชุดเดียวกับผู้เล่น** (อ่านจาก `color` ใน data)
- **Reroll สีศัตรู:** เริ่ม 10g เพิ่ม **ถาวร** ครั้งละ 10g (10→20→30...)
- **ชนะแล้วได้ reward เป็นสีเดียวกับศัตรูที่เพิ่งสู้**
- **Reroll reward:** เริ่ม 10g เพิ่มครั้งละ 10g แต่ **รีเซ็ตทุกหน้า reward**
- Trade-off: รีโรลสีคุมได้ทั้ง "ความยาก" และ "ของรางวัล" พร้อมกัน

## 9. Reward
- ชนะ → สุ่มการ์ด 3 ใบ เลือก 1
- reroll ได้ (ดูราคาข้อ 8.3)
- เวฟรุ้ง / effect พิเศษ → สุ่มจาก pool สายรุ้งล้วน

## 10. Win / Lose
- **แพ้:** ศัตรูถึงฐาน หรือ ยูนิตเราตายหมด → จบ Run แสดงสรุป (floor ที่ไปถึง, ทองสะสม, ศัตรูที่ฆ่า)
- **ชนะ:** ยังไม่มี win condition ตายตัว — เป็น endless ไต่ floor (จะใส่ทีหลังก็ได้)

## MVP Scope (เวอร์ชันแรกใน Godot)
เป้าหมาย: **วงจรเล่นครบก่อน** แล้วค่อยขยายด้วย data

- กระดาน 5×5 + วางการ์ด + merge
- **การ์ดสีฟ้าอย่างเดียวก่อน ~6-8 ใบ** (ทหาร 3, ป้อม 2, สิ่งก่อสร้าง 2, tome 1)
- ศัตรู 2-3 ชนิด
- planning → combat → reward → floor ถัดไป
- gold + ร้านค้า
- แพ้/สรุป Run

ทุกอย่างเกินจากนี้ = **เพิ่มไฟล์ `.tres` ไม่ใช่แก้ engine**

## Open Decisions (ต้องเคาะตอนเริ่ม)
1. **มุมกล้องสนามรบ** — top-down เต็มตัว (ศัตรูเข้าได้หลายทิศ) หรือ lane-based แบบ prototype (ศัตรูเข้าจากขวาอย่างเดียว)? *แนะนำ: lane-based ก่อน เพราะ prototype พิสูจน์แล้วว่าสนุกและง่ายต่อ AI*
2. **ฐานหลัก (base) วางบนกระดานหรือเป็นของตายตัว?** — prototype ให้วางบนกระดานได้ (มีหลายแบบ) *แนะนำ: คงไว้ เป็นจุดเด่นของเกม*
3. **จำนวนช่องที่ล็อกตอนเริ่ม** และวิธีปลดล็อก
4. **200+ ยูนิตท้ายเกม** — ถ้า Godot Node ไม่ไหว จะ fallback เป็น MultiMeshInstance2D หรือลดเพดานจำนวน?
