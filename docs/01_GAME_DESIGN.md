# Kingdom Battle — Game Design Document (Godot 2D)

> Source of truth ของ **"เกมเล่นยังไง"**
> ตัวเลขทุกตัวเป็น starter value ที่จูนได้ → เก็บใน `.tres` ไม่ hardcode
> เอกสารนี้ถอดมาจากเกมเวอร์ชัน HTML/JS ที่เล่นได้จริงแล้ว (prototype ผ่านการเทสต์มาหลายสิบเวอร์ชัน)

---

## 1. Concept
- แนว: **roguelite deckbuilder + auto-battler**
- แรงบันดาลใจ: เกม 9 Kings (ทำเพื่อฝึกทำเกม 2D)
- 1 Run = เดินไปตาม **แผนที่สถานี (station map)**: สลับสถานี combat กับสถานีพิเศษ (ร้าน/พร/ขยายพื้นที่) — วางการ์ด → จบเทิร์น → ดูกองทัพสู้อัตโนมัติ → ได้รางวัลการ์ด → สถานีถัดไป (ดูข้อ 3)
- **ฐาน (บ้าน) มี 3 HP** — แพ้เวฟ = เสีย 1 HP (ยังได้รางวัลปกติ), HP หมด = จบ Run (ดูข้อ 10)
- **จบเกม (ชนะ) = พิชิตบอสที่ floor 30** (ไม่ใช่ endless แล้ว — ดูข้อ 8.2 / 10)

## 2. โครงสร้างสำคัญที่สุด — กระดาน ≠ สนามรบ
**นี่คือจุดที่ต่างจากเกม tower-defense ทั่วไป และต้องเข้าใจให้ถูกก่อนเขียนโค้ด**

```
   PLANNING BOARD (5×5)              BATTLEFIELD (2D top-down)
   ┌───┬───┬───┬───┬───┐            ┌──────────────────────────┐
   │⚔️ │🏹 │   │🔒 │🔒 │            │ 🏰   ⚔️⚔️⚔️      👹👹👹 │
   ├───┼───┼───┼───┼───┤            │      🏹🏹        👹👹    │
   │🏹 │🗼 │🌾 │🔒 │🔒 │   ──────►  │ ฐาน  🗼          👹👹👹 │
   ├───┼───┼───┼───┼───┤   spawn    │                          │
   │   │   │   │🔒 │🔒 │            │ ซ้าย=เรา      ขวา=ศัตรู  │
   └───┴───┴───┴───┴───┘            └──────────────────────────┘
   การ์ด 1 ใบ = 1 ช่อง               การ์ด 1 ใบ = N ยูนิตในสนาม
```

- **กระดาน 5×5 (25 ช่อง)** = ที่วางการ์ด เป็น puzzle เชิงพื้นที่ (การ์ดหลายใบมีผลกับ "ช่องรอบๆ")
- **เริ่มปลดล็อกแค่ 3×3 กลาง (9 ช่อง)** — วงนอก 16 ช่องล็อก ปลดล็อกระหว่าง run ด้วยอีเวนต์/การ์ดบางใบ (เช่น tome)
- **wave 0:** ได้การ์ด "ฐาน" 1 ใบ **บังคับวางลงกระดาน** ก่อนเริ่มเล่น (ดูข้อ 4.1)
- **สนามรบเป็นคนละหน้าจอ** — ตอนจบเทิร์น การ์ดบนกระดานจะถูก "แปล" เป็นยูนิตในสนามรบ
- การ์ดทหาร 1 ใบออกได้ทั้งฝูง: **จำนวน = `base_count × level`** (บวกเชิงเส้น ไม่ใช่คูณทบ — ดูข้อ 4.3)
- **การ์ดไม่ตายตอนสู้** — ยูนิตตายในสนามรบ แต่การ์ดยังอยู่บนกระดาน เวฟหน้าสปอว์นใหม่เต็มจำนวน

## 3. Core Loop — แผนที่สถานี (Station Map)
1 Run = เดินผ่าน **สถานี (floor)** ทีละอัน ตามลำดับที่วางไว้ล่วงหน้า (ดูข้อ 8.4). แต่ละสถานีมีชนิด:

| ชนิดสถานี | เกิดอะไร | จบสถานีเมื่อ |
|---|---|---|
| **combat** | planning (วางการ์ด) → เริ่มรบ → **reward การ์ด** → ไปต่อ | เลือก reward |
| **shop** | ร้านค้า (ซื้อ/reroll) เปิดเป็น window ทับกระดาน | กด "ไปต่อ" |
| **blessing** | เสนอ **พร 1 อย่าง** (รับ หรือ reroll) window ทับกระดาน | รับพร |
| **expand** | เลือกช่องล็อกติดพื้นที่ → ปลดล็อกฟรี 1 ช่อง | คลิกช่อง |
| **boss** (floor 30) | เหมือน combat แต่ **ชนะ = จบเกม (ชนะ)** | ชนะ/แพ้ |

```
plan → COMBAT → reward → plan → SHOP → plan → COMBAT → reward → plan → BLESSING → ... → BOSS(30)
```

**หลักการสำคัญ (event = overlay บน planning):**
- planning board เป็น **ฐานเสมอ** — สถานี shop/blessing/expand โผล่เป็น **window ทับกระดาน** ไม่ใช่หน้าจอแยก
- **ระหว่างอยู่ใน event เล่นการ์ดไม่ได้** (วาง/ใช้/ขาย/รบ ถูกล็อก) — **ดู stat ได้อย่างเดียว**
- กด **"ดูกระดาน" (peek)** ปิด window ชั่วคราวเพื่อดู setup ได้ (ยังอยู่ใน event) — ต้องจบ event ก่อนถึงเล่นการ์ดได้ปกติ
- **จบ event ใดๆ = เข้า planning ของสถานีถัดไปเสมอ** (สถานีพิเศษไม่ติดกัน มี combat คั่นเสมอ → หลัง event เป็น combat = เล่นการ์ดได้)

**1 สถานี combat:**
1. **Planning** (turn-based ไม่มีเวลาจำกัด) — วางการ์ด, merge (Lv≤3), ใช้ tome/buff, reroll สีศัตรู
2. กด **"เริ่มรบ"** → **End-of-Turn resolve** (ยิง effect สิ่งก่อสร้าง เช่นฟาร์ม +count, ช่างตีเหล็ก +dmg — โชว์เลขบัฟเด้งเรียงลำดับบนกระดาน) → เข้าสนามรบ
3. **Combat** (realtime auto-battle ดูอย่างเดียว) — สปอว์นเรา+ศัตรู, ทุกคนหาเป้า/เดิน/ยิงเอง (ตายเป็นศพค้างในสนาม)
4. **Reward** — สุ่มการ์ด 3 ใบ (สีที่เพิ่งสู้) เลือก 1 (reroll ได้) **แพ้/ชนะได้เท่ากัน** → ไปสถานีถัดไป

## 4. Card System

### 4.1 หมวดการ์ด (kind)
| kind | ความหมาย | ในสนามรบ |
|---|---|---|
| `soldier` | ทหาร | สปอว์น N ตัวตาม level เดินไปสู้ (N = `base_count × level`) |
| `base` | ฐานหลัก (บ้าน) | อยู่กับที่ **โจมตีได้** ศัตรู "แตะ" = จบเวฟ (ไม่มี HP bar โดนตีพัง) |
| `turret` | ป้อมโจมตี | อยู่กับที่ ยิงศัตรู ส่วนใหญ่ `untargetable` (ศัตรูตีไม่โดน) |
| `building` | สิ่งก่อสร้าง | 2 แบบ: **กำแพง** (`max_hp>0` ลงสนาม HP เยอะ ให้ศัตรูรุมตี) / **ซัพพอร์ต** (ฟาร์ม ฯลฯ ไม่ลงสนาม ทำงาน `on_end_turn`) |
| `buff` | บัฟถาวร | ไม่ลงสนาม — ใช้กับ **ทหารเท่านั้น** เพิ่ม "ความสามารถ" แบบ stack (ดูข้อ 4.5) |
| `tome` | คัมภีร์ใช้ครั้งเดียว | ไม่ลงสนาม — เพิ่ม stat / effect ครั้งเดียวแล้วหาย |

> `base` / `building` / `turret` = **"สิ่งก่อสร้าง"** — โค้ดใช้ `is_structure()` helper ไม่ไล่เช็คทีละ kind
> **แยก "ลงสนามไหม" ด้วย `max_hp>0` หรือ `attack>0`** ไม่ใช่แยกด้วย kind (กำแพงกับฟาร์มเป็น `building` เหมือนกัน)
> **โครงสร้างเดียวที่มี HP โดนตีได้ = กำแพง** (base = แตะจบเวฟ, turret = untargetable)

#### กฎการ์ดฐาน (base) — พิเศษ
- **wave 0 บังคับวาง 1 ใบ** ลงช่องใน 3×3 กลาง ก่อนเริ่มเล่น
- **มีได้ฐานเดียวบนกระดาน** + **ทำลาย/ทิ้งไม่ได้**
- **โจมตีได้** เหมือนป้อมประจำที่
- **level up เหมือนการ์ดปกติ** — ใช้การ์ดฐานใบใหม่วางทับฐานเดิม (การ์ดฐาน**หาได้จากร้าน/รางวัลปกติ** แต่ตอนวาง **บังคับซ้อนฐานเดิมเสมอ** วางเป็นฐานที่ 2 ไม่ได้)
- **ขายฐานได้ ยกเว้นใบสุดท้าย** — ได้ฐานเกินมาขายทิ้งได้ ตราบใดที่ยังเหลือฐานอื่น (บนกระดาน หรือในมือ) — กันขายฐานใบเดียวตอนยังไม่วาง (จะเล่นต่อไม่ได้)
- **มือเริ่มต้น** = ฐาน 1 ใบ + **สุ่มทหาร 3 ใบ** (`RunConfig.start_cards`) — เว้นการ์ดศัตรู debug
- เชิงโค้ด: กฎทั้งหมดเช็คจาก `kind == BASE` เท่านั้น (ไม่ผูกชื่อการ์ด)

### 4.2 สี (color) — สำคัญต่อระบบ reward
`mint` `green` `gold` `gray` `red` `blue` `purple` `orange` `indigo` `rainbow`

- แต่ละสีมีธีมของตัวเอง (blue = ยุทธวิธี/น้ำแข็ง, red = เลือด/ปีศาจ, gold = เศรษฐกิจ, gray = เครื่องจักร ฯลฯ)
- `rainbow` = การ์ดหายาก ได้จาก reward พิเศษเท่านั้น ไม่โผล่ในร้านปกติ
- **สีจะกลายเป็นแกนหลักของระบบเวฟ** (ดูข้อ 8)

### 4.3 Level & Merge
- Lv 1 → 2 → 3 (**cap 3 เฉพาะการ์ดผู้เล่น** — ศัตรู level ทะลุ 3 ได้ เพราะมีแค่ base×level ไม่มีบัฟ ดูข้อ 8.1)
- วิธีขึ้นเลเวล: merge การ์ดชนิดเดียวกัน, ใช้ tome "อัปเกรด", effect จากสิ่งก่อสร้าง
- **stat หลัก (hp/atk/aspd) โตแบบ compound %:** `stat × (1 + growth)^(level-1)`
- **จำนวนทหารโตแบบบวกเชิงเส้น:** `count = base_count × level + บัฟ flat`
  เช่น `base_count = 3`, บัฟถาวร +2 → Lv1 = 5, Lv2 = 8, Lv3 = 11
- **โครงสร้าง (base/turret/กำแพง) level up = สเตตัสแรงขึ้น จำนวนคงที่ 1** (สูตร `×level` ใช้กับ soldier เท่านั้น)

### 4.4 Card Data Schema
```
id, display_name, icon, color, kind
hp, attack, attack_cd, move_speed, attack_range, splash
base_count: int              # จำนวนทหารพื้นฐาน (soldier); โครงสร้าง = 1
growth: { hp, attack, attack_speed }   # compound % ต่อ level
abilities: { ability_id: base_stacks } # ความสามารถทหาร (soldier)
effects: [EffectData]        # tier 1 declarative
hooks: on_end_turn, on_death, on_spawn, on_upgrade   # tier 2 script
```

### 4.5 Buff / Ability / Stat System
ระบบเพิ่ม stat มี **4 ระบบแยกกัน** (อย่ายัดรวมเป็น pipeline เดียว) — รายละเอียด storage อยู่ใน architecture doc ข้อ 5

1. **stat ตัวเลข (hp/atk/aspd/count)** — เก็บ `current` บน card instance แล้ว **mutate ตามลำดับที่ได้บัฟ** (`%` = ×, `flat` = +, level up = ×growth). ถาวร ไม่มีวันถอนคืน → ไม่ต้องเก็บ log
   - **ลำดับมีผล:** `100 →×2 →+50 = 250` ต่างจาก `100 →+50 →×2 = 300` — การ mutate ตามลำดับรักษาไว้ได้ฟรี
   - บัฟ **%** พบบ่อยสุด (end-turn สิ่งก่อสร้าง +1%/+2% รัวๆ, level, tome, event) — บัฟ **flat** หายาก (tome ไม่กี่ใบ + สกิลทหาร)
2. **buff card = ความสามารถ (ability)** — ใช้กับ **ทหารเท่านั้น** เก็บเป็นถุง `{ability_id: stacks}` เพิ่มพฤติกรรมใหม่ (ดูดเลือด, chain lightning, slow, ระเบิดตอนตาย) **stack ได้** (ดูดเลือด 25% ×2 = 50%) — ไม่ยุ่งตัวเลข stat, ทำงานผ่าน hook ตอนสู้
3. **บัฟชั่วคราวตอนสู้** — เช่น "บัฟเร่งสปีด": attack speed **×(1 + 0.01×stacks) ต่อวินาที คูณทบต้น** หายเมื่อจบเวฟ
   - คำนวณแบบ **pure function ของเวลา** `mult = pow(1 + 0.01*stacks, floor(combat_time))` → ไม่ต้อง loop, ไม่เก็บต่อตัว, จบเวฟรีเซ็ตเอง
   - **sample ตอนยิงเท่านั้น** (ตั้ง cooldown รอบหน้าตอนยิงเสร็จ) → ตัวตีช้าไต่ช้า ตัวตีเร็วพุ่งไว (emergent จาก prototype เดิม)
4. **base + growth** — read-only ใน `CardData`

## 5. Combat Model
- **Realtime, fixed logical tick** (แนะนำ 30 ticks/วินาที) แยกจาก render framerate
- ต่อ 1 tick แต่ละยูนิต:
  1. หาเป้าที่ใกล้ที่สุดในฝ่ายตรงข้าม
  2. ถ้าอยู่ใน range → โจมตี (cooldown ตาม attack_speed)
  3. ถ้าไม่อยู่ → เดินเข้าหา
  4. ถ้าไม่มีเป้าเลย → ศัตรูเดินหน้าเข้าหาฐานเรา
- **Melee** = ตีโดนทันที
- **Ranged เป้าเดี่ยว** = **homing (ล็อกเป้า)** — วิ่งตามเป้าจนโดน (ยิงตัวเคลื่อนที่ไม่พลาด)
- **Ranged splash** = **ballistic เส้นตรง** — เล็งพิกัดเป้า ณ ตอนยิง วิ่งตรงไปถึงแล้ว "ตก" ระเบิด AoE (`splash`)
- **Pierce** (บาริสต้า, `CardData.pierce`) = ballistic เส้นตรงจนสุดแมพ **ทะลุโดนศัตรูทุกตัวในเส้นทาง** (ตัวละครั้ง, เช็คชนแบบ segment กันทะลุข้ามตัว)
- โครงสร้าง (`turret`) `immobile = true` และส่วนใหญ่ `untargetable = true` (ศัตรูตีไม่โดน)
- **ลำดับเป้าของศัตรู:** ทหารเรา (soldier) → กำแพง (building มี HP) → ฐาน (base) — ตีของที่ตีได้ก่อน หมดแล้วค่อยวิ่งไปเป้าถัดไป
- **จบเวฟ (แพ้):** ทหารเราตายหมด → ศัตรูวิ่งเข้าฐาน → **ศัตรู 1 ตัวแตะฐาน = จบเวฟทันที บ้าน −1 HP** (ยังได้รางวัล)
- **ชนะเวฟ:** ศัตรูตายหมดก่อนมีตัวแตะฐาน
- **จบ Run:** บ้าน HP = 0 (แพ้เวฟปกติ 3 ครั้ง หรือแพ้เวฟ Boss 1 ครั้ง = −3)

## 6. Hook System (หัวใจของการขยายเกม)
แทนที่จะเขียน `if card.id == "farm"` กระจายทั่ว engine → การ์ดแต่ละใบ **ประกาศพฤติกรรมตัวเอง**

| Hook | ยิงเมื่อ | ตัวอย่างการ์ด |
|---|---|---|
| `on_end_turn(state, card, idx)` | จบเทิร์น ก่อนเข้าสนามรบ | ฟาร์ม (+ทอง), ศาลเจ้า (สุ่มอัปเลเวล), ป้อมเลือด (สังเวยทหารรอบข้าง) |
| `on_death(state, unit)` | ยูนิตตายในสนามรบ | แพะ (ให้ทอง), ระเบิด (ระเบิดใส่รอบตัว) |
| `on_spawn(state, unit)` | ตอนสปอว์นเข้าสนามรบ | ทหารที่มีบัฟตอนเกิด |
| `on_upgrade(state, card, idx)` | การ์ดขึ้นเลเวล | ไข่สายรุ้ง (Lv3 = ฟักเป็นรางวัล), เครื่องย้อนเวลา (Lv3 = ย้อน floor) |

**กติกา:** engine รู้จักแค่ hook — ไม่รู้จักชื่อการ์ดใดๆ ทั้งสิ้น

## 7. Economy
| แหล่งทอง | หมายเหตุ |
|---|---|
| ฟาร์ม / ตลาด | ได้ทุกจบเทิร์น ตาม level |
| ฆ่าศัตรู | การ์ดบางใบเท่านั้น |
| ~~ชนะเวฟ~~ | **ไม่มีโบนัสชนะ** — แพ้/ชนะได้รางวัลเท่ากัน (แรงจูงใจคือรักษา HP บ้าน) |
| การ์ดตายที่มี `on_death` ให้ทอง | เช่นแพะ |
| พร "มั่งคั่ง" | +10 ทองทุกเวฟ (ต่อ stack) |

ใช้ทอง: ซื้อการ์ดในร้าน (สถานี shop), reroll ร้าน, reroll reward, reroll สีศัตรู, reroll พร (สถานี blessing)

## 8. Waves & Difficulty
### 8.1 การสเกล (ค่าที่จูนมาแล้วจาก prototype)
```
scale  = (1 + (floor-1) × 0.13) × 1.062^(floor-1)     # คูณ HP และ ATK ศัตรู
count  = 3 + ceil(floor² × 0.24)                       # จำนวนศัตรู
```
ผลลัพธ์เป้าหมาย (ทดสอบแล้ว):

| Floor | scale | HP ตัวแท็ง | จำนวนศัตรู |
|---|---|---|---|
| 5 | 1.93 | 72 | 9 |
| 10 | 3.73 | 138 | 27 |
| 20 | 10.88 | 403 | 99 |
| 30 | 27.30 | **1010** | **219** |

> **โมเดลเวฟ = องค์ประกอบการ์ด (ไม่ใช่ fix จำนวนยูนิตแล้วสุ่มเติม):** แต่ละเวฟกำหนดเป็น "เด็คศัตรู" — การ์ดชนิดไหน Lv เท่าไร กี่ใบ (เช่น ตัวเก่ง Lv5 × 4 ใบ + ตัวเน้นจำนวน Lv5 × 6 ใบ) แล้วแต่ละใบสปอว์น `base_count × level` เหมือนฝั่งเรา → ปรับความยากด้วย **จำนวนใบ/level/ส่วนผสม** ไม่ใช่สุ่มเติมยูนิตให้ครบเลข (จะเสียสมดุลเพราะตัวเก่ง vs ตัวเน้นจำนวนน้ำหนักไม่เท่ากัน)
> **ศัตรู level ทะลุ 3 ได้** (ไม่มี cap แบบผู้เล่น) เพราะศัตรู**ไม่มีบัฟ/ability/ของพิเศษเลย** มีแค่ base stat × level เพียวๆ → level คือปุ่มปรับความแรงเดียว
> สูตร `scale`/`count` ข้างบน = **งบความยากรวม** ที่ WaveGen เอาไปกระจายเป็นการ์ด (จูนจริงตอน M4)
> ปรัชญา: **ศัตรูเน้นจำนวนเป็นหลัก** — ฝั่งเราไม่เกิน ~700, ฝั่งศัตรูเยอะสุดเท่าที่ทำได้
> ⚠️ เป้าจริง **~2,000–3,000 ยูนิตพร้อมกัน 60 FPS** (GDScript ล้วนไหว) → ดู performance note ใน architecture doc

### 8.2 เวฟพิเศษ
- **Boss wave = floor 30 (สถานีสุดท้าย)** — **ชนะบอส = ชนะเกม (จบ Run แบบชนะ)**, แพ้บอส (ยังมี HP) = เล่นบอสใหม่, HP หมด = จบ Run แบบแพ้
  - *(ตอนนี้บอสยังเป็นเวฟปกติ scale floor 30; ยูนิต/กลไกบอสพิเศษ = งานทีหลัง)*
- **Rainbow battle**: สถานีพิเศษที่วางแผนไว้ (ยังไม่ทำ) — ศัตรูแข็งกว่าปกติ ชนะได้การ์ดสายรุ้ง

### 8.3 ระบบสีเวฟ (ฟีเจอร์ที่วางแผนไว้ — ทำใน M4)
- ก่อนเข้าสู้ เกมสุ่ม **"สีศัตรู"** 1 สี → ศัตรูทั้งเวฟเป็นการ์ดสีนั้นล้วน
- ศัตรูใช้ **การ์ดชุดเดียวกับผู้เล่น** (อ่านจาก `color` ใน data) — **ไม่มี roster ศัตรูแยก**
  - ทหาร/ความสามารถ/sprite เหมือนฝั่งเราเป๊ะ ต่างแค่ **สี HP bar** (เรา=เขียว, ศัตรู=แดง) ไม่ tint รูป
  - *(M2 ใช้ `goblin` เป็น placeholder ชั่วคราว จนกว่า M4 จะสลับไปสร้างศัตรูจากการ์ดผู้เล่นตามสีเวฟ)*
- **Reroll สีศัตรู:** เริ่ม 10g เพิ่ม **ถาวร** ครั้งละ 10g (10→20→30...)
- **ชนะแล้วได้ reward เป็นสีเดียวกับศัตรูที่เพิ่งสู้**
- **Reroll reward:** เริ่ม 10g เพิ่มครั้งละ 10g แต่ **รีเซ็ตทุกหน้า reward**
- Trade-off: รีโรลสีคุมได้ทั้ง "ความยาก" และ "ของรางวัล" พร้อมกัน

### 8.4 ระบบสถานี (Station Map) — วางแผนล่วงหน้า
- **ลำดับสถานีวางไว้ล่วงหน้าทั้ง run** (`wave_track` เก็บ `{type, color}` ต่อ floor) → แถบสถานีด้านบนโชว์ **ย้อนหลัง 2 + ปัจจุบัน + อนาคต** (สีวงกลม = สีเวฟ, ไอคอน = ชนิดสถานี)
- **cadence:** สถานีพิเศษมาทุก 8 เวฟ คนละจังหวะ → **shop@`floor%8==3`, blessing@`==5`, expand@`==7`**, ที่เหลือ combat; boss@30
- **สถานีพิเศษไม่ติดกัน** — มี combat คั่นเสมอ (floor หลัง event = combat = ได้ planning เต็ม)
- สีเวฟที่โชว์ล่วงหน้า = สีที่เจอจริงตอนถึง (reroll สีเปลี่ยนเฉพาะสถานีปัจจุบัน)

### 8.5 พร (Blessing) — สถานี blessing
- **universal run buff, stack ได้** — เสนอ **1 อย่าง** (รับ หรือ reroll +10g ถาวร)
- ผลกับ **ทุกอย่างที่เข้าเงื่อนไข + การ์ดที่วางทีหลังด้วย** (คำนวณตอนสปอว์นทุกครั้ง ไม่ bake ลงการ์ดปัจจุบัน)
- ชุดเริ่มต้น: `+50% dmg ทุกการ์ด` · `HP ทหาร x2/stack` · `+30% คริ (บวกตรงๆ)` · `+1 count ทุกเวฟ` · `+10 ทองทุกเวฟ` · `ลดราคาร้าน 50%/stack`

## 9. Reward
- **reward = event overlay หลังจบทุกสถานี combat** (แพ้หรือชนะก็ได้) → สุ่มการ์ด 3 ใบ (สีที่เพิ่งสู้) เลือก 1 → ไปสถานีถัดไป
- reroll ได้ (เริ่ม 10g +10 ต่อครั้ง รีเซ็ตทุกหน้า)
- บอส (floor 30) **ไม่มี reward** (ชนะ = จบเกม)

## 10. Win / Lose
- **บ้านมี 3 HP** (แสดงเป็นหัวใจ 3 ดวงบน HUD)
- **แพ้เวฟปกติ** (ศัตรูแตะฐาน) = เสีย **1 HP** — เวฟจบทันที **แต่ยังได้รางวัลปกติ** เล่น floor ต่อได้
- **แพ้เวฟ Boss** = เสีย **3 HP รวด**
- **จบ Run (แพ้) เมื่อ HP = 0** → แสดงสรุป (floor ที่ไปถึง, ทองสะสม, ศัตรูที่ฆ่า)
- **ชนะเวฟ** = ฆ่าศัตรูหมดก่อนมีตัวแตะฐาน (ไม่เสีย HP)
- **ชนะ Run = พิชิตบอส floor 30** → หน้าจอ "ชนะแล้ว" (ไม่ใช่ endless แล้ว)

- planning → combat → reward → floor ถัดไป

- แพ้/สรุป Run

## Decisions (เคาะแล้ว 2026-08-06)
1. **มุมกล้องสนามรบ** — ✅ **lane-based top-down** (ศัตรูมาจากขวา, บ้านซ้าย) + sprite เต็มตัวมองจากบน → อัปเป็น 2.5D/ไอโซเมตริกทีหลังได้ (sim ≠ render ไม่ต้องแก้ core)
2. **ฐานหลัก (base)** — ✅ วางบนกระดาน, ตัวเดียว, บังคับ wave 0, ทำลายไม่ได้, อัปเลเวลด้วยการซ้อน (ดูข้อ 4.1)
3. **ช่องล็อกตอนเริ่ม** — ✅ เริ่ม 3×3 กลาง (9 ช่อง), วงนอก 16 ช่องล็อก, ปลดล็อกด้วยอีเวนต์/tome
4. **เพดานยูนิต** — ✅ เป้า ~2,000–3,000 ตัว ด้วย `MultiMeshInstance2D` + Structure-of-Arrays (ไม่ต้อง GDExtension)

## Decisions (เคาะแล้ว 2026-08-07)
5. **แผนที่สถานี** — ✅ station map แทน endless: combat + สถานีพิเศษ (shop/blessing/expand ทุก 8 เวฟ คนละจังหวะ ไม่ติดกัน), boss@30 = ชนะเกม (ดูข้อ 3, 8.4)
6. **event = overlay บน planning** — ✅ shop/blessing/expand เป็น window ทับกระดาน, ระหว่าง event เล่นการ์ดไม่ได้ (peek ดูได้), จบ event ค่อยไปต่อ
7. **พร (blessing)** — ✅ universal buff เสนอทีละ 1 (รับ/reroll), stack ได้, ผลกับการ์ดที่วางทีหลังด้วย (apply ตอนสปอว์น) (ดูข้อ 8.5)
8. **reward** — ✅ กลับมาเป็น event หลังทุก combat (สุ่ม 3 เลือก 1 สีที่เพิ่งสู้)
9. **base + starter hand** — ✅ base หาได้ปกติ, ขายได้ยกเว้นใบสุดท้าย, มือเริ่มต้น = ฐาน + สุ่มทหาร 3 ใบ (ดูข้อ 4.1)
